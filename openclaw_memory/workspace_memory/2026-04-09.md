#### 权限排查与SFTP问题
**问题现象**：用户通过SFTP客户端看不到 `/tmp/tang_legend_videos/` 目录中的文件
**用户截图显示**：SFTP客户端界面（中文）显示 `/tmp/` 目录，有 `ClawMem`、`openclaw`、`vmware` 等文件夹，但无 `tang_*` 文件夹

**根本原因分析**：
1. **文件属主问题**：文件由root用户创建，用户可能以非root用户（如ubuntu）连接SFTP
2. **SFTP客户端缓存**：目录列表未刷新
3. **权限过滤**：某些SFTP客户端可能隐藏或过滤root创建的文件
4. **路径混淆**：用户可能查看 `/temp/` 而不是 `/tmp/`

**解决方案实施**：
1. **文件验证**：确认文件确实存在且可访问
   ```bash
   # 文件确实存在
   ls -la /tmp/tang_legend_videos/
   # 文件大小：82MB
   # 修改时间：今天12:20
   ```

2. **创建软链接**（更易访问）：
   ```bash
   ln -sf /tmp/tang_legend_videos /tmp/tang_videos
   ln -sf /tmp/tang_split /tmp/tang_split_parts
   ```

3. **复制到用户目录**（解决权限问题）：
   ```bash
   # 检查用户
   id ubuntu  # 用户存在
   # 复制文件并修改属主
   cp -r /tmp/tang_legend_videos /home/ubuntu/
   cp -r /tmp/tang_split /home/ubuntu/
   chown -R ubuntu:ubuntu /home/ubuntu/tang_legend_videos
   chown -R ubuntu:ubuntu /home/ubuntu/tang_split
   ```

4. **新的可访问路径**：
   - `/home/ubuntu/tang_legend_videos/`（推荐，ubuntu用户所有）

#### 技术经验总结
**重要发现**：
1. **文件属主与SFTP可见性**：root创建的文件可能对非root用户SFTP客户端不可见
2. **软链接的有效性**：创建软链接不会改变文件属主，但提供更易访问的路径
3. **用户目录复制**：将文件复制到用户主目录（如 `/home/ubuntu/`）是最可靠的解决方案
4. **SFTP客户端差异**：不同客户端（FileZilla、WinSCP、Cyberduck）的缓存和过滤行为可能不同

**推荐最佳实践**：
1. **工作文件存放**：建议将用户工作文件存放在用户主目录而非 `/tmp/`
2. **权限设置**：创建文件时考虑目标用户权限需求
3. **缓存管理**：告知用户SFTP客户端刷新方法
4. **多路径访问**：提供多个访问路径（原始路径、软链接、用户目录）

## 🎯 学习要点

### 关于Linux文件系统
1. `/tmp` 是系统级临时目录，位于根目录 `/` 下一层
2. `/temp` 不是标准Linux目录，可能是笔误
3. `/tmp` 权限：`drwxrwxrwt`（所有用户可读写，粘滞位）
4. `/tmp` 文件可能被系统清理，不适合长期存储

### 关于用户权限
1. **root用户**：系统管理员，创建的文件属主为root
2. **普通用户**（如ubuntu）：通常无法直接访问root文件
3. **SFTP限制**：某些SFTP客户端可能隐藏或限制root文件显示
4. **解决方案**：`chown` 修改属主 或 `cp` 复制到用户目录

### 关于大文件传输
1. **Telegram限制**：文件大小限制（约50MB）
2. **分割方案**：`split` 命令分割，`cat` 命令合并
3. **SCP方案**：`scp user@ip:source destination`
4. **HTTP临时服务**：`python3 -m http.server 8080`
