### 规则二：分钟级MACD回溯检测规则（2026-02-26 确立）⭐

**背景**：东方财富11:00死叉漏报事件

**规则内容**：
- 日线以下级别（60/30/15/5分钟）监控必须实现**回溯检测**
- 不只检查最后一根K线，要**向前回溯至少4小时**的K线
- 发现交叉即返回，记录信号发生的**具体时间**
- 必须实现**去重机制**，同一信号只报告一次

**回溯配置**：
| K线级别 | 回溯K线数 | 覆盖时间 |
|---------|-----------|----------|
| 60分钟 | 4根 | 4小时 |
| 30分钟 | 8根 | 4小时 |
| 15分钟 | 16根 | 4小时 |
| 5分钟 | 48根 | 4小时 |

**详细规则文件**：`skills/stock/rules.md`

### 规则三：数据获取失败报告规则（2026-02-27 确立）⭐

**背景**：中顺洁柔数据获取失败，海哥要求了解失败原因以便手动查看

**规则内容**：
- 所有监控脚本必须检测并记录数据获取失败的情况
- 数据获取失败时，必须向用户报告**具体原因**（API错误、网络超时、数据源不可用等）
- 即使没有信号触发，数据获取失败也需要通知用户
- 用户可根据失败原因决定是否手动查看或调整监控配置

**实施要求**：
1. **错误捕获**：监控脚本中所有外部API调用必须有try-catch，捕获并记录异常信息
2. **原因分析**：区分不同类型的失败（网络错误、API限制、数据格式异常等）
3. **用户通知**：在监控报告中包含失败股票、失败原因、建议操作
4. **持续改进**：记录常见失败模式，优化数据源选择策略

**适用范围**：所有A股监控脚本（MACD、价格提醒、资金流向、新闻监控等）

### 规则四：监控频率与回溯检查规则（2026-02-27 确立）⭐

**背景**：价格提醒监控每5分钟太频繁，调整为每30分钟一次，但需要确保不漏检小于监控频率的时间周期指标

**规则内容**：
- **监控频率调整**：所有高频监控（如价格提醒）调整为每30分钟执行一次，避免过度频繁的API请求
- **回溯检查要求**：对于小于监控频率的时间周期指标（如5分钟级别），监控脚本必须检查从上一次监控时间点之后的所有数据点，而不仅仅是当前时刻的数据
- **检查范围计算**：例如30分钟监控一次，对于5分钟指标，需要检查过去30分钟内的6个5分钟K线
- **信号去重**：同一信号在监控周期内只报告一次，避免重复通知
- **时间对齐**：监控执行时间应与交易时间对齐（如9:30、10:00、10:30等）

**实施要求**：
1. **Cron调整**：所有高频监控cron从`*/5`调整为`*/30`，且只在交易时间内执行
2. **脚本增强**：监控脚本必须记录上次检查时间，并基于该时间进行回溯检查
3. **数据缓存**：考虑缓存最近的数据以避免重复API请求
4. **性能优化**：回溯检查不应显著增加执行时间，需优化数据获取逻辑

**适用范围**：所有基于时间序列的监控脚本（MACD、价格提醒、资金流向等）
